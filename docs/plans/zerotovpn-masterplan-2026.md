## 1. Executive direction

ZeroToVPN already has meaningful discovery signals, but the site is not converting that discovery into enough organic clicks yet. The next phase is not “publish thousands more pages”; it is to turn existing impressions into qualified visits, make the strongest topic clusters unmistakable to search engines, and remove indexation noise.

The operating model is:

1. Find pages and queries already showing demand.
2. Improve their title, snippet, intent match, evidence and internal-link position.
3. Build a small number of deep topical clusters around proven themes.
4. Keep the sitemap curated while allowing genuinely useful pages to be discovered naturally.
5. Measure rankings, clicks, conversions and AI citations as separate outcomes.

- Add links to Russia, China, Telegram, obfuscation and protocol guides.
- Add FAQ blocks that answer the exact query variants found in Search Console.

### Cluster B — VPN selection by use case

Free VPN, streaming, gaming, Android/iPhone, Windows, travel, public Wi-Fi, privacy and cheap VPN pages remain useful, but each cluster needs one canonical hub and a limited number of supporting pages. Avoid creating a page for every superficial keyword variation.

### Cluster C — VPN research and trust

Methodology, speed testing, no-log verification, leak tests, protocol explainers, privacy policy analysis and provider reviews should support every commercial comparison. This is the proof layer that differentiates ZeroToVPN from thin affiliate sites.

## 6. Technical and indexation rules

### Sitemap policy

- Include canonical, indexable, useful URLs with a 200 response.
- Exclude redirect-only routes, noindex pages, duplicate locale fallbacks and thin programmatic variations.
- Keep dynamic pages discoverable when they are genuinely useful; sitemap omission alone is not a reason to 404 them.
- Re-submit or request a read in Search Console after substantial sitemap changes.

### URL audit buckets

Every URL should end in one of these states:

| State | Action |
|---|---|
| Valuable and indexable | Keep 200, self-canonical, include in sitemap when strategic |
| Valuable but not yet in sitemap | Keep 200 and link contextually; add after validation |
| Duplicate or parameter variant | Canonicalize, redirect or block the source of duplication |
| Thin/obsolete | Merge, 301 or noindex based on replacement quality |
| Redirect-only | Keep out of sitemap |
| Restricted/unsafe affiliate context | Keep educational content if useful, remove affiliate CTA |

## 7. DataForSEO research pipeline

For each cluster, save a local dossier containing:

- seed keywords and related terms;
- monthly volume, difficulty, intent and trend;
- live SERP results and SERP features;
- PAA questions;
- competitor domains and overlapping rankings;
- recommended page, search intent and business value;
- source date, endpoint and cache key.

Use the API cost-consciously: cache every response, start with a small keyword set, and expand only after the cluster hypothesis is validated.

## 8. Content and page template standard

Every money-adjacent or high-intent page should contain:

1. Intent-matched title and introduction.
2. Short answer / recommendation block.
3. Comparison table with test date and methodology link.
4. Pros, limitations and who should not choose the provider.
5. Evidence links and clear uncertainty where data changes.
6. FAQ/PAA section.
7. Related cluster links.
8. Affiliate disclosure before or alongside the first commercial CTA.
9. No fake urgency, unassigned coupons, forced popups or irrelevant provider promotion.

## 9. Measurement dashboard

Track weekly by cluster, not only sitewide:

- impressions, clicks, CTR and average position;
- keywords in positions 1–3, 4–10, 11–20 and 21–40;
- indexed URLs, sitemap URLs and canonical mismatches;
- organic landing-page engagement;
- affiliate clicks and conversion rate by compliant page;
- referring domains and meaningful backlinks;
- AI response appearances and cited URLs.

The first KPI review should compare Iran, Russia, Telegram and the free-VPN cluster separately. Sitewide averages hide the opportunities.

## 10. Google Drive evidence package

Use the Drive package as an evidence layer, not as an unstructured screenshot archive. For each screenshot or export, record:

- source product (GSC, Ahrefs, DataForSEO, affiliate dashboard);
- date and time range;
- metric definition;
- URL/query/page represented;
- decision it supports;
- whether it is current, historical or anecdotal.

Screenshots are useful for context, but CSV/API exports should be the source of truth for prioritisation. Once the folder is shared or connected, process it in this order: GSC exports → Ahrefs/competitor exports → SERP screenshots → affiliate evidence → historical plans.
